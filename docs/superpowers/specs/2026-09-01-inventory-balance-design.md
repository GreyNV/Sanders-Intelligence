# Inventory Balance Design

**Prepared:** 2026-09-01
**Surface:** `/purchasing/inventory-balance`
**Primary users:** purchasing and admin users
**Admin controls:** opening period and opening inventory value

## Objective

Build a purchasing-owned inventory balance rollforward that starts from an admin-entered beginning inventory value and period, then calculates monthly ending inventory using received PO value less COGS from sales.

## Routing and Access

- Add a Purchasing nav item labeled `Inventory Balance`.
- Route: `/purchasing/inventory-balance`.
- Visible to `admin` and `purchasing`.
- Admins can edit the beginning balance period and value.
- Purchasing users can read the rollforward but cannot edit seed values.

## Accounting Contract

The monthly balance formula is:

```text
beginning_inventory_value + po_received_value - cogs_amount = ending_inventory_value
```

The next month's beginning inventory value is the prior month's ending inventory value.

### Beginning Balance

- Admin sets one opening month and amount.
- The opening month represents the first month whose beginning balance is manually anchored.
- Only one active opening balance is needed for this release.
- If no opening balance exists, the page shows a clear empty state and the admin edit panel.

### PO Received Value

- PO receipts are based on SellerCloud received quantity changes observed during purchase order sync.
- A receipt movement is recorded once when `qty_units_received` increases for a PO item.
- Receipt value is `received_delta_units * unit_price`.
- Receipt period is based on the timestamp when the sync observes the increased received quantity.
- Decreases to received quantity are recorded as negative receipt movements so the rollforward remains reconcilable.
- Existing current-state PO rows are not enough to rebuild historical receipt timing before this feature starts tracking deltas. Historical months before receipt tracking may require manual seed values or a one-time backfill if source receipt history becomes available.

### COGS

- COGS is derived from SellerCloud P&L order cost, not estimated from current SKU cost.
- `sales_daily` should store a period-queryable `cogs_amount` value alongside revenue.
- When an order cost applies to multiple sales lines, allocate the order-level COGS across lines using the same allocation basis already used for revenue where possible.
- If P&L cost is missing for a sales row, store `0` for that row and expose a data quality count in the rollforward summary.
- Sales date basis remains `shipDate`, matching the existing `sales_daily.sale_date` contract.

## Data Model

### `inventory_balance_settings`

One-row settings table for the active opening balance.

Columns:

- `id uuid primary key default gen_random_uuid()`
- `settings_key text not null unique default 'active'`
- `beginning_period_month date not null`
- `beginning_inventory_value numeric not null default 0`
- `updated_by uuid references public.users(id)`
- `updated_at timestamptz not null default now()`
- `created_at timestamptz not null default now()`

Security:

- Enable RLS.
- Grant authenticated users read access through policies restricted to active `admin` and `purchasing` users.
- Grant writes only to active admins.
- Revoke all access from `anon`.

### `po_receipt_movements`

Append-only receipt ledger generated by PO sync.

Columns:

- `id uuid primary key default gen_random_uuid()`
- `po_item_id integer not null`
- `po_id integer not null references public.purchase_orders(id) on delete cascade`
- `source_sku text not null`
- `planning_sku text`
- `received_delta_units numeric not null`
- `unit_price numeric not null default 0`
- `received_value numeric not null default 0`
- `observed_at timestamptz not null default now()`
- `source_updated_on timestamptz`
- `sync_run_key text`
- `created_at timestamptz not null default now()`

Indexes:

- `observed_at`
- `po_id`
- `po_item_id`
- `planning_sku`

Security:

- Enable RLS.
- Active `admin` and `purchasing` users can read.
- Client writes are not granted.
- Service-role sync writes bypass RLS from Edge Functions and local maintenance scripts.

### `po_items`

Keep current columns and add a snapshot column:

- `last_balance_received_units numeric`

The sync compares incoming `qty_units_received` to `last_balance_received_units`, inserts a movement for the delta, then updates `last_balance_received_units`.

### `sales_daily`

Add:

- `cogs_amount numeric not null default 0`
- `cogs_source text`

Existing revenue behavior remains unchanged.

## Query and Hook Design

Add `app/src/hooks/useInventoryBalance.ts`:

- `useInventoryBalance(periodMonth: string)`
- `useUpdateInventoryBalanceSettings()`

The query should:

1. Load active settings.
2. Build a month window from `beginning_period_month` through the selected period.
3. Fetch monthly PO receipt totals from `po_receipt_movements`.
4. Fetch monthly COGS totals from `sales_daily`.
5. Return one row per month with beginning, receipts, COGS, ending, and data quality counts.

Missing relation handling can return a setup-required state for local development, but production should use the migration before exposing the page.

## UI Design

Create `app/src/pages/purchasing/InventoryBalance.tsx`.

Primary layout:

- Page header with month selector controls.
- KPI strip: selected ending balance, PO received, COGS, net change.
- Admin-only opening balance panel with month input, amount input, and save button.
- Main rollforward table:
  - First date of the month
  - Beginning inventory value
  - New PO amount received
  - COGS in the time period
  - Total inventory value
  - End of the month
- Compact formatting suitable for repeated finance review.

Empty and warning states:

- No opening balance: show setup prompt and admin controls.
- No receipt ledger yet: show `PO receipt tracking starts after the migration and next PO sync`.
- Missing COGS rows: show a small warning count without blocking the table.

## Tests

Add helper tests first for:

- Month rollforward carries ending balance into the next month.
- PO receipt values increase inventory.
- COGS deducts inventory.
- Negative receipt movements reduce inventory.
- Missing COGS rows produce a data quality count.

Add hook/static tests for:

- Supabase queries paginate period movement rows.
- Purchasing route and sidebar item are wired.
- Admin edit controls are present but guarded by role checks.

Add Edge/static tests for:

- `sync-sales` persists `cogs_amount`.
- PO sync inserts receipt movements only when received quantity changes.
